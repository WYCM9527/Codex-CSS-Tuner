# Cursor CSS Tuner

在 Cursor 内置浏览器里点选元素，拖动数值、改文字、改组件的属性或在兄弟之间换位置，实时看效果，满意了一键写回源码，每一条都能单独还原。

[English](https://github.com/WYCM9527/Cursor-CSS-Tuner/blob/main/packages/extension/README.md) · 简体中文

![选中卡片，拖动内边距和圆角，再把两条改动应用到源码](https://raw.githubusercontent.com/WYCM9527/Cursor-CSS-Tuner/main/docs/media/hero.zh-CN.gif)

它要解决的事只有一件：**在 Cursor 里调样式、改文字、调顺序、改属性、看效果，再把效果应用到代码里**。写回由确定性的引擎完成，不经过 AI；引擎处理不了的改动，会整理成提示词预填进新的 Agent 对话，由你按回车发送。

## 能做什么

- **点选元素**：在内置浏览器的页面上悬停高亮、点击选中。面板用大白话说出选中的是什么，后面跟着它的文字开头（比如“标题 “欢迎””），并标出写在哪个文件；“图层”分区列出它周围的元素，同一处 JSX 或模板渲染出的所有实例会在页面上标出来。
- **调参面板**：布局（flex / grid）、间距、尺寸、定位、文字、填充、描边、圆角、投影、效果、CSS 变量。数值可拖动、可滑动，颜色有取色器；默认对齐到主题里的值和 CSS 变量，按住 Alt 可以调任意值。填充和描边还可以用线性或径向渐变：改角度，点渐变条加颜色点，拖动颜色点改位置，每个颜色点都能选主题里的颜色。
- **增删属性**：没有填充、描边或投影的元素，点对应分区上的 + 直接加上，点 − 去掉。来自源码声明的值右上角都有 ×，点了删掉这条声明（Tailwind 删掉对应的类名），元素回到没有它时的样子；继承来的值、初始值和框架预设样式没有可删的。
- **撤销、重做和重置**：改动清单在面板顶部，默认收成一行（点一下展开看每一条）。“全部应用”左边的上一步 / 下一步（在面板里也可以按 ⌘Z / ⇧⌘Z，或 Ctrl+Z / Ctrl+Shift+Z）在还没应用的改动之间前进后退；有未应用改动的参数，右上角会出现重置按钮。改动清单随时同步。
- **改文字**：面板的“内容”分区列出选中元素里的文字，遇到 `<b>` 这类行内标签会分成几段。可以在面板里改某一段，也可以在页面上双击选中元素里的文字直接输入；回车加进改动清单，Esc 撤销。
- **兄弟换序**：在页面上拖选中元素标签旁边的把手，或在“图层”里拖它那一行，或点下面的上移 / 下移按钮。页面上的新顺序用 CSS `order`（flex 和 grid）或位移摆出来，不移动真实的 DOM 节点，所以应用前这条改动会标成“仅预览”。
- **改组件属性**：面板的“组件属性”分区列出渲染选中元素的那个组件在调用处收到的属性。字符串、数字、布尔值可以改；`cva` / `tailwind-variants` 配方的变体和字符串字面量联合类型（来自 TypeScript）会列成选项，调用处没写的变体也会列出来。页面通过 React 的 DevTools 钩子立刻显示新值，同一个调用处创建的实例一起变。服务端组件在页面上只读，应用后生效。
- **实时预览**：改动先只作用在页面上，不碰源码。
- **确定性写回**：点“应用”后按元素的来源写回：
  - Tailwind 类名（Tailwind 4；Tailwind 3 的主题来自 `tailwind.config`）：JSX 里的字符串和模板字符串、`clsx` / `cn` / `twMerge` 参数、`cva` 的基础类和变体、类名常量、组件调用处传进去的 `className`；Vue 和 Svelte 组件里是 `class` 属性、`:class` 的字符串 / 数组 / 对象字面量、`class:` 指令，以及使用组件处写的 `class`。当前生效的响应式变体（如桌面宽度下的 `md:px-5`）只改那一个。刻度外的值写成任意值类名（可在设置里改成交给 Agent）。渐变写成 `bg-linear-*` / `bg-radial`（Tailwind 4）或 `bg-gradient-to-*`（Tailwind 3）加 `from-*` / `via-*` / `to-*`，这些类表达不了的写成任意值。删属性时去掉设置它的类；这个类还管着要保留的属性时（只删左内边距，写的是 `p-4`）不删，面板会说明原因。
  - 普通 CSS：改命中的那条规则里的声明，简写属性按位置改（`padding: 16px 20px → 24px 20px 16px`）；支持嵌套 `&`、`@import` 进来的文件和 CSS Modules（带哈希的类名会映射回源码里的类名）。Vue 的 `<style scoped>` 和 Svelte 的 `<style>` 改组件文件里的样式块，带 `:deep()`、`:global()` 这类写法的选择器按源码原样匹配。没有规则设置这个属性时，加到元素自己的规则里，优先选不在 `@media` 这类条件里的，换个窗口宽度也生效。渐变填充写进 `background-image`，原来只写了颜色的 `background` 简写会删掉。删属性时删掉这条声明；盒模型和描边的简写还管着要保留的属性时，剩下的部分改写成长写（`padding: 8px 14px` 删掉左右内边距后变成 `padding-top: 8px; padding-bottom: 8px`），`font`、多层 `background` 这类简写删不了一部分。
  - CSS 变量：改定义处（`:root`、Tailwind 的 `@theme`），用到它的地方一起变；Tailwind 自带的变量（如 `--spacing`）会写进 `@theme`。
  - 文字：改 JSX 里的文字。组件渲染的是传进来的 prop 时，改调用处的字符串（`<Card title="…">` 或子元素），只影响这一处用法。来自 `t('key')` 的文案（react-i18next、next-intl）改页面当前语言的 JSON 文件，语言先看地址里的语言段（`/zh/…`），再看 `<html lang>`。纯 HTML 改 HTML 文件里的文字，`&`、`<` 这类字符会重新转义。
  - 顺序：JSX 里写死的兄弟，在父元素的 JSX 子节点里挪位置，单独一行写在某一项上面的注释跟着它走；用 `.map()` 渲染、数组是常量字面量（同一个文件里，或通过相对路径导入）的列表，改数组里元素的顺序。纯 HTML 改 HTML 文件里的子元素，`<script>`、`<style>` 这类元素留在原处。
  - 属性：改组件调用处的属性。写的是字面量就地改，引号保持原样；调用处没写的属性加到这个调用上。调用处还有展开写法（`{...rest}`）时，面板会提醒展开的值可能盖掉它。
- **应用后校验**：写盘后等开发服务器热更新，核对页面上的计算样式、文字、顺序和属性与预览时一致；热更新较慢、或写的文件让开发服务器整页刷新时（Vite 里改翻译文件、Next.js 的 webpack 模式里改 CSS Module），会在后台继续等，页面重新连上后再核对。
- **逐条还原**：文件在应用后没被改过时按快照字节级恢复；改过的话只回退这一处，找不到原样就停下并给出对比，不会覆盖你后来的修改。
- **只改这个还是全部**（Tailwind）：“只改这个”只改选中的这一个元素（组件用 `cn` / `twMerge` 合并类名时，在用到组件的地方加类名）；“全部”改组件本身和它的变体，所有用到它的地方一起变。两种改法会改到代码里不同地方时才给这个选项，“全部”后面标着页面上会变几个元素。
- **交给 Agent**：写不回去的改动（比如类名来自变量拼接，文字由 `{count} 个条目` 这样的代码生成，属性传的是 `size={size}` 这样的表达式，列表来自 props、接口数据，或者给没有填充色的元素加渐变描边）生成结构化提示词，连同它来自的代码一起预填进新的 Agent 对话，不会自动发送。
- **中英双语**：面板、通知和交给 Agent 的提示词跟随 Cursor 的显示语言（简体中文或英文）；也可以点面板顶部的“中 / EN”切换，选择会记在 `cssTuner.language` 设置里。

## 支持的项目

| 技术栈 | 状态 |
| --- | --- |
| React 18 / 19 + Vite，Tailwind 4 | 已验证 |
| React + Vite，Tailwind 3（主题来自 `tailwind.config`） | 3.4 已验证 |
| React + Vite，普通 CSS / CSS Modules | 已验证 |
| Next.js 16 App Router，`next dev`（Turbopack）和 `next dev --webpack`，服务端组件和客户端组件 | 已验证 |
| react-i18next、next-intl，JSON 翻译文件 | 文字编辑已验证 |
| 组件属性 | React 18 / 19 和 Next.js 的客户端组件已验证；服务端组件能写回，不能预览 |
| Vue 3 + Vite，Nuxt 4（`nuxt dev`） | 只改样式（类名和样式块），已验证 |
| Svelte 5 + Vite，SvelteKit 3（`vite dev`） | 只改样式（类名和样式块），已验证 |
| 纯 HTML + CSS（用内置服务打开） | 改 CSS 规则、文字和顺序 |

页面必须跑在开发模式下：元素到源码的定位依赖 React 开发构建的调试信息、Vue 和 Svelte 开发态挂在元素上的位置信息，以及开发服务器的 sourcemap。

## 安装

在 Cursor 的扩展面板搜索 **Cursor CSS Tuner** 安装；也可以从 [GitHub Releases](https://github.com/WYCM9527/Cursor-CSS-Tuner/releases) 下载 `.vsix`，在扩展面板右上角的菜单里选“从 VSIX 安装…”。需要最新版 Cursor。

## 快速开始

1. 启动项目的开发服务器（如 `npm run dev`）。
2. 点活动栏里的 CSS Tuner 图标，在“调参”面板里填页面地址并打开；页面会在 Cursor 内置浏览器的标签页里打开，不需要改项目代码、不需要装任何依赖。
3. 点“选取元素”，在页面上点一个元素。
4. 拖动面板里的数值，页面实时变化；改动会出现在面板顶部的清单里，上一步 / 下一步可以前进后退。要改文字，在“内容”分区里改，或者在页面上双击它。要在兄弟之间换位置，拖页面上元素标签旁边的把手，或拖“图层”里它那一行。要改它所属组件的属性，用“组件属性”分区。
5. 点“应用”写回源码；之后可以对任意一条点“还原”或“对比”。

纯 HTML 项目：在资源管理器里右键 HTML 文件或文件夹，选“CSS Tuner: 用内置服务打开 HTML 文件”。

## 命令

| 命令 | 说明 |
| --- | --- |
| CSS Tuner: 打开页面 | 在内置浏览器里打开开发服务器的页面并注入调参脚本 |
| CSS Tuner: 选取元素 | 开关页面上的点选模式 |
| CSS Tuner: 应用全部改动 | 把清单里所有待应用的改动写回源码 |
| CSS Tuner: 用内置服务打开 HTML 文件 | 给没有开发服务器的 HTML 起一个本地静态服务 |
| CSS Tuner: 把剩下的改动交给 Agent | 生成提示词并预填进新的 Agent 对话 |
| CSS Tuner: 自检 | 在单独的标签页里实际跑一遍注入、连接、选中、预览和刷新后重新注入 |

## 设置

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| `cssTuner.language` | `auto` | 面板和提示用的语言：`auto` 跟随 Cursor 的显示语言，也可以设成 `zh-CN` / `en`。面板顶部的“中 / EN”改的就是这个设置 |
| `cssTuner.defaultUrl` | `http://localhost:5173/` | 默认打开的地址 |
| `cssTuner.remBase` | `16` | rem 和 px 换算用的根字号 |
| `cssTuner.snap` | `true` | 数值自动对齐到主题里的值和 CSS 变量（按住 Alt 可以填任意值） |
| `cssTuner.tailwind.scope` | `instance` | Tailwind 项目里默认只改选中的这一个（`instance`，面板上的“只改这个”），还是改组件本身（`source`，“全部”） |
| `cssTuner.tailwind.arbitraryValues` | `allow` | 主题里没有的值直接把数值写进类名（`allow`，如 `px-[13.5px]`），或交给 Agent（`agent`） |
| `cssTuner.css.strategy` | `editRule` | 普通 CSS 的改动直接改元素用到的那条规则（`editRule`），或交给 Agent（`agent`） |
| `cssTuner.vars.strategy` | `editDefinition` | CSS 变量的改动直接改定义的地方（`editDefinition`），或交给 Agent（`agent`） |
| `cssTuner.verifyTimeoutMs` | `8000` | 应用后等页面刷新、再核对页面和预览是否一致的最长时间（毫秒），超时的改动会在后台再等一轮 |

## 限制

- **只支持 Cursor**：扩展通过 Cursor 内置浏览器的内部命令（`cursor.browserView.*`）注入脚本，这些不是公开 API，Cursor 更新后可能变化。扩展启动时会检查这些命令是否还在，缺失时会提示；也可以随时运行“CSS Tuner: 自检”。
- **换序只在同一个父元素里**：不会增加、删除元素，也不会把元素挪到别的父元素下。来自 props、state、接口数据、`filter()` / `sort()` 结果或 `let` 变量的列表，源码里的顺序改不了，交给 Agent。
- **换序预览是模拟的**：flex 和 grid 用 `order`，其他布局用位移把元素挪过去；遇到浮动、绝对定位或折行的行内内容，预览和应用后的效果可能略有差别。
- **文字按单行纯文本改**：换行会变成空格；`<b>` 这类行内标签留在原位，它前后的文字各自单独改。只改当前语言的翻译文件，其他语言保持原样。由代码生成的文字（表达式、模板字符串、自己写的翻译函数、`t.rich`）和带占位符的翻译交给 Agent。
- **属性**：只列出调用处写了的属性，另外加上组件传给自己配方的 `cva` / `tailwind-variants` 变体（同名传、整个 props 对象传或展开传）。对象、函数和元素只读。预览要在页面加载时接上 React，所以调参脚本连上之前就开着的页面需要刷新一次，面板上有按钮。TypeScript 给出的选项来自 TypeScript 语言服务，大项目里它启动要几秒。
- **Vue 和 Svelte 只改样式**：文字、换序和属性交给 Agent。模板必须是 HTML（不支持 Pug），只改普通 CSS 的 `<style>` 块，`lang="scss"`、`less`、`stylus` 的样式块交给 Agent。`node_modules` 里的组件、以及没有模板的 Vue 组件（渲染函数、JSX）渲染出的元素，定位到你的代码里使用这个组件的标签：Vue 只有组件的根元素能定位过去，因为 `class` 只透传到根元素（`inheritAttrs: false` 时也不透传）；Svelte 写在那里的类名要组件自己把 `class` 属性用上才生效。只支持 Vite 开发服务器，Nuxt 和 SvelteKit 用的就是它。
- **Next.js 的源码定位**借用开发服务器给错误浮层用的内部接口 `/__nextjs_original-stack-frames`，同样不是公开 API；Turbopack（`next dev`）和 webpack（`next dev --webpack`）两种开发模式都验证过。服务端组件的热更新可能要几秒，校验会等。webpack 模式下改 CSS Module 可能让 Next.js 整页刷新。
- **热更新的边界情况**：热更新之前就渲染出来、热更新之后才第一次选中的元素，可能定位到旧的行号；位置看起来不对时刷新一下页面。
- **CSS Modules** 的类名映射是按“哈希类名里包含的最长源码类名”匹配的，自定义了 `generateScopedName` 的项目可能对不上。
- **Tailwind 只支持 v3 和 v4**：设计系统从项目自己的 `node_modules` 加载。Tailwind 3 项目的主题读 `@config` 指定的 `tailwind.config.*`，没写的话从入口往上找到项目根为止最近的那个；类名的写法和 Tailwind 4 一样。扩展不改 `tailwind.config`：刻度外的值写成任意值类名，或者按设置交给 Agent，提示词会指明配置文件。不支持 Tailwind 3 的 `prefix` 选项。
- **渐变描边用两层背景叠出来**（`background-clip: padding-box, border-box`）：圆角保留，但元素要有不透明的填充色，没有的话交给 Agent；渐变描边只能是实线。圆锥渐变、图片和多层背景在面板里只显示、不能改，换成纯色或渐变会把它们替换掉。
- **上一步 / 下一步只管还没应用的改动**：应用之后历史清空，要撤回已经写进源码的改动，在清单里逐条还原。
- 文件在编辑器里有未保存的修改时，应用和还原会停下，避免覆盖。
- 应用直接写磁盘、不走“编辑 + 保存”，所以不会触发保存时格式化，还原才能做到字节级一致。

## 安全与隐私

- 调参脚本只通过 Cursor 内置浏览器注入到你打开的标签页里，不走代理，也不改项目代码。
- 页面和扩展之间的 WebSocket 只监听 `127.0.0.1`，并要求随机 token。
- 扩展不访问外网；Next.js 项目只会请求你自己的开发服务器。

## 排查问题

- 日志在“输出”面板的 **CSS Tuner** 频道。
- 运行“CSS Tuner: 自检”，会列出每一项检查的结果。
- 页面的 CSP 拦住 WebSocket 时，扩展会自动改用 `executeJavaScript` 通道，功能不变，只是稍慢。
- 选中元素后面板显示“没有找到源码位置”：确认页面由开发服务器以开发模式提供（React 项目还要是 React 的开发构建）。
